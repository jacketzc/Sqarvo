作用域：`backend/` 全部（`backend/apps/backend-service`、`backend/apps/sqarvo-mcp`、`backend/crates/*`）。根
`AGENTS.md` §1–§5、§9、§13、§15 恒定适用；本文件承载根 §2、§4.2、§6、§7.3/7.4（实现侧）、

## 2. 运行时与传输（根 §2 细则）

- 独立伴生进程 + Tokio 异步运行时；引入其他运行时须 ADR 说明必要性与边界。
- `parent-watch` 监听宿主前端进程；进程退出时连接、cursor、临时文件的清理路径必须存在。
- 配置加载、日志分级、服务健康状态归后端；所有日志输出必须过 §9 脱敏（凭据、完整连接串、私有路径）。
- 传输（UDS / 命名管道 / 回环 TCP + 令牌）藏在 Transport 抽象后；业务层与 rpc-server 之外的代码不得感知具体实现。
- 后端绝不包含平台 UI 逻辑，不依赖 WinUI / GTK / SwiftUI / AppKit。

## 4.2 后端职责

连接与会话生命周期；SQL 执行、取消与结果集管理；事务与隔离级别、数据库能力检测；元数据与对象信息；数据导入导出与未来迁移；Driver SPI 与方言适配；配置、日志、健康状态、资源清理。

- 前端可预校验，后端必须再校验权限、参数范围、资源状态、操作合法性。
- 不把 Rust 内部结构体、Trait 对象、第三方驱动类型暴露进跨进程协议。

## 6. Driver SPI（决策：ADR 0003/0005/0006/0008/0009/0011）

### 6.1 核心原则
- 项目自有、尽量稳定的 SPI，与具体驱动库尽可能独立。
- 内置驱动编译进后端：`backend/crates/drivers/<database>/` workspace member；不建平行的第二处驱动目录（Rust workspace 是构建/测试/依赖单元）。
- 初期不引入 Rust 动态库插件 ABI（无可依赖的跨版本稳定 ABI）；进程外插件是未来选项。
- 每种数据库的连接、元数据、方言、事务、专门能力放清晰的实现边界内；共享接口只表达真正可复用的能力，数据库特有内容经 capability descriptor / 类型化扩展暴露。

### 6.2 不等价假设
- Database / Catalog / Schema / Namespace / Owner / Sequence / Package 等概念不折叠进一个含糊字段。
- 共享元数据模型保留对象类型、原类型名、完全限定名与必要的库特定信息；不丢字段精度、长度、符号性、时区、字符集、排序规则、默认值。
- 不支持的特性显式返回 unsupported / 能力状态，绝不静默模拟成功。
- SQL 方言与 DDL 由对应驱动处理；通用业务逻辑里不得散落数据库名条件分支。

### 6.3 数据类型与结果集
- 不得把所有值表示为 String。覆盖 NULL、bool、有/无符号整数、浮点、Decimal、文本、二进制、日期、时间、带时区 timestamp、JSON、数组、库特有值。
- Decimal 等精度敏感类型不得无条件转浮点；无法无损表示时保留原类型信息并采用显式展示/导出策略。
- 大二进制与超大文本设计延迟/分块拉取（BLOB/大字段 deferred retrieval）。

### 6.4 驱动生命周期
每个驱动必须定义：连接/断开/测试连接与错误分类；会话所有权与并发规则；查询执行、取消、结果集关闭、资源清理；事务支持与隔离级别能力；元数据获取与分页策略；驱动版本、支持的数据库版本范围、能力声明。
- 不假设所有驱动有相同的异步行为；阻塞驱动用 blocking task pool，不得占用 Tokio 关键 worker。

### 6.5 驱动测试
- 新/改驱动必须通过 `driver-testkit` 符合性测试（连接、元数据、事务、执行、取消、结果集、类型映射）。
- 集成测试用专用数据库与合成数据：口径见 `docs/database/mariadb.md`、`docs/database/sqlite.md`；测试容器编排见 `tests/integration/`。

## 7.3 / 7.4 结果传输与取消的实现侧（契约规则在 `proto/AGENTS.md`）

- 查询结果：Query ID、结果集元数据（列类型/精度/可空/展示提示）、批量拉取或流式、取消、资源关闭、背压。
- 表浏览：游标/分页拉取；排序与过滤能力显式声明；分页排序稳定性有定义。
- 多语句、多结果集、update count 语义明确（ADR 0006）；超大字段延迟检索。
- 取消尽量传播到驱动；取消幂等，重复取消不得崩；客户端断开后 Session/Cursor/临时文件必须可清理。
- 消息大小、并发查询数、缓冲设合理上限；大结果用流式解决，不靠放大消息上限。

## 10. 性能与资源管理

- 先建立可复现基准再优化；内存限制覆盖查询结果、导入导出、对象树、大文件操作。
- 用流式/批处理避免不必要的拷贝与序列化；并发上限、超时策略、取消机制齐备。
- 不使用无界 channel、无限任务创建、无界缓存制造响应假象。
- 无测量不宣称「零开销」「极致性能」。

## 11. Rust 编码规范

- 遵循 rustfmt 与 clippy；必须豁免 lint 时局部抑制并写明原因。
- 公开类型、Trait、模块、复杂算法写文档注释；错误类型提供上下文并支持分类，避免把所有错误转成无信息 String。
- 少用 `unwrap()/expect()/panic`，仅限已确立不变式处并说明理由；不跨 `.await` 持锁，除非必要且已论证。
- 共享状态用清晰所有权模型，不过早引入 `Arc<Mutex<...>>` 复合结构。
- 外部输入、SQL、文件路径、Protobuf 字段、数据库元数据都要校验。
- `unsafe` 克制使用，文档化安全不变式并加针对性测试。
- 新增依赖前评估维护状态、许可证、构建足迹、平台支持与安全历史（引入新 runtime/大依赖属根 §15.2 确认项）。

## 13. 后端测试要求

- 单元：业务规则、数据类型转换、SQL 方言、错误映射、生命周期行为。
- 契约与安全：见根 §13；安全测试覆盖日志脱敏、凭据存储、IPC 访问控制、路径校验、错误信息不泄露。
- 环境跑不了的检查明确记录「未跑 + 原因」，不声称通过。

## sqarvo-mcp（stdio MCP Server）

- 独立 stdio 进程；流程模型见 `docs/architecture/mcp.md`（ADR 0032），工具面契约见 `docs/api/mcp-tools.md`，SQL 只读策略见 ADR 0033。
- 与 backend-service 共用 Driver SPI 与根 §9 凭据红线；直连数据库仅经驱动，不绕过 SPI。
- MCP 是独立交付物：不引入 UI 逻辑；stdio 输入按不可信外部输入校验（同 §11）。
