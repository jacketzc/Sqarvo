# ADR 0038 · MCP 显式事务的所有权与撤权顺序

状态：已接受（维护者确认 #4）。关联 ADR 0008、0035、0036、0037 和 REQ-MCP-013。

## 背景

单次写入拥有独立会话，在一次请求内完成事务。显式事务会跨请求保留数据库锁和会话，
必须能在请求消失后清理。HTTP 使用全局共享凭据。CLI 和桌面服务可在不同进程修改写入策略。

## 决策

采用每个事务一个专用数据库会话和所有者任务。stdio 以服务生命周期为边界，
HTTP 以认证后活跃的 MCP Session 为边界。任务串行处理有界队列，复用 V2 逐语句预检、
参数化执行和事务终态预算。进程内 Registry 管理配额、路由和短期终态摘要。
空闲或绝对期限、所有者消失、策略或共享文档修订变化均可触发清理。

复用共享档案的跨进程锁。COMMIT 写入持久审计意图后，在共享锁下做最终策略和档案校验，
持锁派发并等待应答或终结超时处置；撤权和档案变化持独占锁。提交先取得锁并完成派发时，
其应答和恢复可能晚于撤权，但禁止重新派发提交。撤权先落盘时，事务只能回滚。

## 备选与取舍

给现有查询会话附加跨请求事务会让普通查询或其他请求进入同一个数据库事务。
按 HTTP 全局 Bearer 归属会把不同 MCP Session 绑定到同一所有者。仅在提交前读取普通快照
会给独占写者留下竞态。使用单独的授权修订可缩小对无关档案编辑的影响，但需要引入持久化字段和兼容处理。

采用整个共享文档修订可识别快速撤销再开启，代价是无关档案修改也触发保守回滚。
提交占用共享锁期间，档案写入可能达到现有的锁等待上限并返回 `profile.locked`。
长时间阻塞的 SQLite 文件 I/O 可能延迟物理关闭，隔离中的会话继续消耗配额。
审计记录及终态摘要均不参与数据库提交，数据库结果仍以数据库应答及事后核对为准。

## 重新评估条件

支持远程 HTTP、跨进程 Session 恢复、独立身份认证或需要更细的策略修订时重新评估。
