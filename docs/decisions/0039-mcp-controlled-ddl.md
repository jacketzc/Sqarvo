# ADR 0039 · MCP 受控 DDL 的专用会话与持久终态

状态：已接受（维护者确认 #5）。关联 REQ-MCP-014、#250、ADR 0037 和 ADR 0038。

## 背景

DDL 可能移除数据、重写表及等待元数据锁。MariaDB 的隐式提交与 SQLite 的原生写事务
具有不同的确认边界。两种驱动都需要确定同一个已检查目标在调用时可以安全变更，
并在数据库响应缺失时避免自动再执行。

## 决策

MCP 继续使用全局启用和只读策略。六个工具共用原有 stdio 和认证 HTTP 分发。
执行只接收封闭的结构化模型。驱动提供方言、标识符引用、元数据检查与派发回执。
MCP 将生成 SQL 解析为单语句 AST，与从规范化计划构造的参考 AST 核对。
缓存读会话及 V2/V2.1 事务从不承载 DDL。现有工具调用和配置语义保持兼容。

SQLite 使用在已有文件上打开的专用会话，执行从 BEGIN IMMEDIATE 起持有写事务。
目标及依赖检查和 DDL 使用同一物理连接，数据库确认 COMMIT 后才报告实际生效。
预览使用只读打开及读快照。从两次读取之间发生的 Schema 变化由实际执行重新核对。
SQLite 原生 ALTER 超出能力时返回不支持。依赖不明确时拒绝。

MariaDB 使用无应用事务的专用会话和明示窄版本基线。服务器实际确认单条语句后报告成功。
DBA 维护专用实例的隔离及完整元数据视图。该实例禁止依赖 ADR 0037 的 MCP DML 部署。
普通业务 DML 权限可以保留。所有 MCP DDL 使用实例命名锁串行化，数据库元数据锁负责实际
对象竞争。DBA 和其他外部 DDL 执行者须遵守维护窗口，先停用并排空 MCP 再变更；
命名锁本身无法约束不参与此协议的客户端。应用事务 ROLLBACK 无法撤销 MariaDB DDL。
11.8.6 是首版支持及定向验证基线。

先持久化意图，随后在 ProfileStore 共享锁内重验策略及档案修订，并把单个命令交给专用
驱动 worker。锁只覆盖有界的本地交接。已交接命令可能在撤权落盘后抵达或完成。
SQLite COMMIT 使用同一授权闸口，使提交前撤权可以触发回滚。驱动命令应答与会话清理
分别报告。取消尽力传播；超时、断连、失去提交确认后的执行结果可以是未知。

本地执行槽与幂等记录由相同用户数据目录的 stdio/HTTP 进程共享。使用独立的 SQLite
状态文件，在派发前保留 operation_id。请求摘要使用系统密钥环中的本地 HMAC 密钥，
状态与 JSONL 均省略默认值和 SQL。JSONL Intent 必须耐久；确认成功后终态审计失败
只附加警告。未确认的意图持久阻断新操作，不能用新 ID 绕过。本机运维核查实例和引擎
终止后可解除屏障，保留原结果；MCP 工具无此入口。JSONL 与数据库各自持久化，日志
用于追踪，数据库对象的真实状态须在数据库核对。

## 备选与取舍

通用 SQL 或通用迁移器会扩大语法、副作用与回滚承诺。仅使用内存锁不能覆盖多个进程、
协议或重启。把 MariaDB DDL 加入现有 V2.1 Session 会引入隐式提交。常规操作使用
独立执行槽，结果缺失后最保守地暂停同部署余下 DDL，换取跨进程防重放。

## 重新评估条件

扩大数据库版本、支持更复杂的对象或让 MariaDB DDL 与 ADR 0037 MCP DML 共用实例前，
重新验证原生语法、权限隔离、隐藏依赖、元数据锁与终态分类。资源上限及部署细节见
[MCP 工具参考](../api/mcp-tools.md#v22-controlled-ddl)。
