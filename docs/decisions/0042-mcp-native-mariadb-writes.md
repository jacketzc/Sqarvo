# ADR 0042 普通 MariaDB 实例的 MCP 写入和结构变更

- 状态：已接受（2026-11-24）
- 更新 [ADR 0037](0037-mcp-bounded-writes.md) 的独立插入规则和
  [ADR 0039](0039-mcp-controlled-ddl.md) 的建表、加列规则。

## 背景

用户开启 MCP 数据访问并关闭只读后，MariaDB 写入仍要求登记档案版本和安装 DBA 资格视图。
结构化 DDL 还要求目标库与档案默认库一致。普通实例难以使用插入、建表和加列。

## 决策

两个 MCP 开关负责应用级授权，数据库使用当前档案的账号和原生权限。已启用的
独立 `insert_rows`、`create_table`、`alter_table.add_column` 可对显式指定的业务库表
执行。直接插入目标限 InnoDB，增列沿用普通可空列的参数限制。
更新、删除、显式事务、删表、删列、重命名和索引变更继续使用既有部署条件。
SQLite 保留既有预检、档案只读与 `main` 语义。

驱动层负责写方言、原生插入目标检查及 DDL 事务语义。MCP 公共层保留参数绑定、操作限额、
审计和授权复核。DDL 继续用 `operation_id` 去重，并保留超时和未知结果核查。

## 取舍

受管部署可以约束或排除间接写入。普通 MariaDB 实例允许数据库定义的外键、触发器和默认值，
因此直接行数限额无法描述所有副作用，事务回滚也只覆盖引擎可回滚的变更。
普通建表和加列预览使用当前账号可见的元数据，最终权限和并发问题由数据库在执行时裁决。
扩展更多操作时需重新评估各操作的影响范围和结果语义。
