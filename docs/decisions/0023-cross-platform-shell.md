# ADR 0023：跨平台窗口外壳的区域一致与原生控件

- 状态：已接受（2026-11-07 评审通过）
- 日期：2026-11-07
- 关联：Issue 待建；REQ-PLAT-001、REQ-UI-001、REQ-A11Y-001；AGENTS.md §8（原生前端）
- 上游：[workspace-model.md](../ui-specification/workspace-model.md) §8

## 背景

v0.2.3 的界面结构来自一张单平台的低保真原型（1200×800，Windows 风格：自绘窗口控制按钮、
窗口内菜单行、双行状态栏）。而 AGENTS.md §8 要求三端各自使用原生控件、不破坏平台交互约定，
且明确禁止为了像素一致牺牲平台习惯。macOS 尤其不可能照搬：菜单必须进系统菜单栏，
窗口内不出现菜单行，窗口控制按钮由系统绘制。

同时，三端必须保持**功能与核心语义一致**：同一操作在三端可完成、状态呈现一致、文案一致。
Windows 与 macOS 前端目前只有窗口骨架（未接后端），因此现在定下的口径会被后续两端照抄，
必须先写清楚「哪些必须一致、哪些必须原生」。

## 备选方案

1. **像素级一致（自绘外壳）**：三端都画同一套标题栏、菜单行、状态栏。视觉统一，
   但在 GTK 与 macOS 上等于放弃原生交互（窗口拖拽、系统菜单、全屏、辅助功能树），
   与 AGENTS.md §8 直接冲突。
2. **区域一致 + 控件原生**：六区域、对象矩阵、状态栏字段、快捷键语义一致；承载控件与
   外观按平台原生实现。像素不一致，但语义可对齐、验收可自动化（按控件语义而非坐标）。
3. **各端自由发挥**：只对齐功能清单。三端会漂移成三个产品，维护与验收成本最高。

## 决策

采用方案 2。

1. **一致的层次**（必须有同一份定义，见 `workspace-model.md`）：
   六个区域的存在与顺序、对象种类 ↔ 信息面板的对应关系、标签的生命周期与关闭语义、
   表格浏览的字段（行号、类型行、分页器、最后刷新）、状态栏必须呈现的会话级信息、
   快捷键语义、六种状态的文案与呈现方式。
2. **原生的层次**（各端自行决定）：
   窗口装饰与窗口控制按钮、菜单的宿主（窗口内 / 系统菜单栏 / 主菜单按钮）、
   标签条的控件与位置、工具条的载体（`GtkBox` / `CommandBar` / `NSToolbar`）、
   状态栏形态（GTK 与 WinUI 双行；macOS 单行细条 + 工具条状态）、控件密度。
3. **不实现自绘窗口控制按钮**：Linux/macOS 交给系统；Windows 使用系统标题栏
   （`AppWindow`），只为容纳菜单行而在内容区顶部加一行，不改窗口装饰。
4. **菜单只出现有实现支撑的项**：文件 / 视图 / 查询 / 表 / 帮助五个集合，
   逐端映射到原生宿主；`Favorites`、`Tools`、`Window` 在 v0.2.3 不出现（无收藏、无工具集、
   无多窗口）；macOS 的「窗口」菜单由系统提供。
5. **标签条**：Linux 用 `AdwTabView` + `AdwTabBar` 放在 chrome 行（libadwaita ≥ 1.6，
   本机 1.9.1 可用）；Windows 用 `TabView`；macOS 用原生 tab。位置与尺寸可不同，
   但「固定 Objects 页 + 对象标签 + 新建」这一结构必须一致。
6. **状态栏语义优先**：三端都必须显示「当前连接 · 事务状态 · 行数/记录位置 · 最后刷新」；
   macOS 允许不叫状态栏，但信息必须在常驻位置可见，不能藏进弹层。
7. **验收按语义不按像素**：自动化证据读取控件文本 / 可访问性名称，不比较截图坐标；
   截图只作为目检材料。像素级对齐不作为任何一项验收标准。

## 取舍

- 三端会长得不一样，用户跨平台切换时会有位置差异；用一致的快捷键与区域顺序降低迁移成本。
- 「语义一致」比「像素一致」更难验收：需要可访问性标签与控件命名规范，不能只靠截图。
- Linux 的紧凑密度（行高 24/32）不适用于 Windows/macOS；同一屏可见行数会不同，
  「一屏多少行」不能写进需求。
- 现在只有 Linux 有真实实现，Windows/macOS 的口径属于**未验证**决定：两端接入时必须
  复核本 ADR 的映射是否成立（尤其菜单宿主与状态栏）。

## 重新评估条件

- Windows 或 macOS 接入时发现某区域无法用原生控件表达（例如双行状态栏在 macOS 上
  与系统习惯冲突）；
- libadwaita 的 tab 组件 API 变化，或需要在 GNOME 上支持 `AdwTabOverview`；
- 出现「三端必须共享同一份布局代码」的诉求（那会与 AGENTS.md §8 冲突，需先改 AGENTS）。
