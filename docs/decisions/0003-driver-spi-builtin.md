# ADR 0003：驱动以内置 crate 形式编译进后端

- 状态：已接受
- 日期：2026-11-04

## 背景

数据库客户端必须支持多个数据库。驱动可以是内置模块、动态库插件或独立进程。
Rust 没有稳定的跨版本 ABI，动态库插件在升级编译器或依赖时会失效。

## 备选方案

1. **内置 workspace crate**：驱动与后端一起编译，注册到 `DriverRegistry`；
2. **动态库插件**（`cdylib` + 自描述 ABI）：可独立发布，但 ABI 不稳定、崩溃会拖垮后端；
3. **独立进程驱动**：隔离最好，但进程管理与性能开销大，第一阶段过重。

## 决策

第一阶段采用方案 1：

- 每个驱动一个独立 crate，仅依赖 `sqarvo-driver-api` 与自身数据库库；
- 通过 `DriverRegistry::with_builtin_drivers()` 编译期注册；
- 驱动类型不泄露到 gRPC 契约或通用业务层。

## 取舍

- 优点：无 ABI 风险；编译器可做全量优化与类型检查；测试与发布简单。
- 代价：新增驱动需要重新发布整个后端；二进制体积随驱动增加；
  不同驱动难以独立升级。
- 缓解：驱动按 crate 隔离，能力通过描述符声明；后续如需独立发布，方案 3（进程隔离）
  比方案 2 更安全。

## 重新评估条件

- 驱动数量增多导致二进制体积或构建时间不可接受（需有测量数据）；
- 需要第三方社区独立发布驱动；
- 需要按驱动隔离崩溃域。
