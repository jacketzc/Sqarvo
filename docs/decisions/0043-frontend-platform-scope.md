# ADR 0043 — 退役旧 Windows 前端与限定主线验收范围

状态：已接受

## 决策

Sqarvo 保持跨平台原生定位。前端开发与发布范围以 [平台状态配置](../../frontend/platforms.toml)
为准。Linux 为 Active，承担主线开发、维护、测试与发布。Windows 为 Rewriting，旧实现退役，
新版在独立工作线开发。macOS 为 Planned，保留规划。只有 Active 前端进入主线日常同步与发版。
Rust 后端、MCP、IPC 安全、公共协议与业务契约继续按实际影响验证跨操作系统兼容性。

旧 C# / WinUI 3 前端及其构建、测试、文档和同步记录可从
`archive/windows-csharp-final`（`e442c8326f2feef3763aa24e2695490e75966c14`）恢复。
Windows 重写工作线使用 `dev/windows-rewrite`，技术选型与原型验证在该工作线进行。
保留旧实现于 Git 历史能支持回查，同时免除主线为退役 UI 持续构建、适配与提交同步证据的成本。
新版重新接入需要自己的组件验收证据。

本决策取代 ADR 0023、0026、0028、0031 中对旧 Windows 实现的控件、度量、主题和文案生成要求，
以及 ADR 0027、0034 中固定平台数量的同步、验收与 Agent 阅读范围。公共行为、度量真值、Linux
工程与质量标准继续适用，ADR 0029 的功能验收边界继续适用。

## Windows 重新接入

完成核心技术验证、可维护且可复现的构建与自包含部署，用户无需手动安装额外运行时。
在真实 Windows 环境验证原生交互，建立可复用的 UI 功能自动化，达到维护者确认的 Linux 核心功能
覆盖要求，并完成对应组件同步验证。恢复 Windows 前端 CI、打包与发版门禁后，由维护者明确
批准将 Windows 状态改为 Active。
