# ADR 0031：界面国际化（i18n）——共享文案源与英文支持

- 状态：**讨论稿（未评审，不作为实施依据）**
- 日期：2026-11-17
- 关联：[REQ-I18N-001](../product/requirements.md)（国际化，P2，未实现）；
  [ADR 0026](0026-ui-scaling-window-sizing.md)（本文接续其「字符串目录」决策，回改其"暂不做 i18n"的量级论证）；
  [ADR 0028](0028-app-theme-preference.md)（偏好持久化与生效方式的同款先例）；
  [ADR 0029](0029-ui-acceptance-boundary.md)（英文档验收仍是交互级，不做图像识别）；
  AGENTS.md §8.1（三端 copy must match）、§8.6（字符串目录、release-check）、§14.3 / §14.4（注册表与发版门禁）
- 里程碑归属：M6 前端接入与硬化（维护者 2026-11-17 拍板；建单另出确认单）

## 背景

AGENTS.md §8.6 早已规定「新增用户可见字符串走 per-crate string catalog，不写字面量」，
但 catalog 机制本身从未落地——仓库现在没有任何 l10n 模块，规矩是悬空的。ADR 0026 当时以
「44000 行里内联中文，加 gettext 是机械但巨大的改动；德语/俄语长 30%，会撑破 12px 紧凑密度」
为由把 i18n 推给未来。本 ADR 就是那个未来：英文界面是产品需求（REQ-I18N-001），0026 的论证
需要被正面处理而不是装作不存在。

现存中文文案字面量分布（脚本粗测，2026-11-17，口径见附录「数字口径」；**UI 候选是上限，
数字用于量级评估，不是迁移清单**——逐区清单由 S1 产出）：

| 端 | UI 候选（需进目录的上限） | 日志 | cfg(test)/夹具 | QA 断言 | expect panic 文案 |
|---|---|---|---|---|---|
| Linux 前端 `frontend/linux/src` | 2288 | 382 | 926 | 295 | 65 |
| Windows 前端（.cs 非测试工程 + .xaml） | 727 + 68 = 795 | — | 测试工程另有 | — | — |
| 后端 `backend/crates,apps` src | 490 | 15 | 257 | — | 14 |

三个关键事实：

1. 后端文案会**原样流进界面**：`frontend/linux/src/backend/client.rs:936` 直接
   `sanitize(status.message())`，`ui.rs:771` 直接 `failure.message()`。英文界面弹中文报错
   是第一版可接受的已知缺口（见「建议决策」第 1 条），S8 跟进。
2. `qa.rs` 的 295 条断言绑定中文文案；语言可切之后 QA 必须钉住 locale，否则英文环境全线误报。
3. Windows 是 net8.0-windows10.0.19041 + WindowsAppSDK 2.6.5：RESW / ResourceLoader /
   `ResourceManagementTools.CurrentUICultureOverride` 原生可用，MSIX 资源裁剪白送。
   proto 里没有任何 locale 字段；主题偏好的先例是 `window.json` 的 `theme` 字段
   （缺=默认，加字段不升版本，#119/#158）。

## 备选方案

1. **各端原生、两份目录**（Linux gettext `.po` + Windows `.resw`，人工对齐）：
   否决。AGENTS §8.1 要求三端 copy 一致，两份目录没有任何机械对账，漂移不可发现；
   extraction 的工作量与共享源方案完全相同，却丢掉了单一真值。
2. **各端自研运行时 catalog（不生成、不共享）**：否决。仍是两份数据源；绕开 RESW 就放弃了
   WinUI 原生资源机制与 MSIX 按语言裁剪；「运行时热切换」优势已被维护者明确排除（重启生效）。
3. **后端文案全量参数化（`ErrorDetail` 变 code + args + template key，前端渲染）**：方向正确
   但整体否决为第一版范围。490 条逐条参数化 + 错误语义变更需要独立契约 ADR，风险与本需求
   （界面支持英文）不成比例。降级为 S8 跟进 Issue。
4. **继续不做**：REQ-I18N-001 是 P2 在册需求，open-source 客户端的英文界面是社区采用的
   门槛，不再拖延。

## 建议决策（待评审）

维护者已于 2026-11-17 就以下全部条款做出选择（三个主分叉 + 七条细节全部按本方案），
待正式评审后状态翻「已接受」。

1. **范围**：第一版只翻两端**界面文案**。后端错误暂留中文；S8 跟进 Issue 登记两条廉价改进——
   高频 `ErrorDetail.code` 的前端英文摘要表（原文照旧进详情），以及是否走「后端双语目录」或
   「文案参数化」的正式定夺。数字 / 日期 / 排序**不做 CLDR 本地化**：ISO 8601、Decimal 原文、
   NULL 与空串区分是行为契约口径，动了是回归。macOS 未接入门禁，不在范围。
2. **单一真值**：仓库根新建 `l10n/<区>.toml`，一个功能区一个文件，每条
   `{ key, zh, en, status }`。分区前缀直接复用 UI 注册表的九个功能区
   （`shell.` `object_tree.` `tabs.` `data_page.` `query.` `dialogs.` `startup.` `inspector.` `info_panel.`
   ——最终以注册表实际 id 前缀为准），不发明第二套地名。
   **zh 是 source of truth**：注册表与行为契约继续记中文原文，本改动不改任何既有中文文案，
   因此不动 spec_hash。翻译只活在 `l10n/`。
3. **生成机制**：构建期从 `l10n/` 生成 Linux 的 Rust catalog 与 Windows 的 `.resw` +
   `Strings.g.cs`（`Strings.T("data_page.btn_refresh")` 式访问器）。XAML 不强求全量
   `x:Uid`，48 条按控件就近处理（x:Uid 或 code-behind 赋值）。**生成失败 = 构建失败**，
   与 `metrics.toml` 生成常量同口径（AGENTS §8.6）。
4. **回落与门禁**：运行时缺 key → 回落 zh → 回落 key 本身，永不空白。构建期 en 缺失不阻断，
   CI 打印缺口清单；**发版前 en 必须清零**，接入 §14.4 `release-check` 同款门禁。
   术语表 `l10n/terms.md` 先冻结一份（提交/commit、事务/transaction、回滚/rollback、
   库/视图/字段等），防止同一中文在不同区译成两个英文词。
5. **插值与复数**：只支持命名占位符 `{n}` 与 `one/other` 两态（「N 行」→「1 row / N rows」）。
   不做完整 CLDR 复数规则，够中 / 英使用。
6. **偏好与生效**：菜单「视图 → 语言」（跟随系统 / 简体中文 / English），持久化为
   `window.json` 的 `language` 字段（缺 = 跟随系统），完全复刻 ADR 0028 主题的读写与兼容路径。
   「跟随系统」映射：`zh*` → 中文，其余 → English。切换后**重启生效**，弹提示并提供一键重启；
   不做运行中热切换。
7. **QA 与验收**：`qa::enabled()` 时语言强制 zh，295 条断言零改动。英文档验收是交互级：
   英文模式冒烟启动不崩、菜单与对话框文案非空且为英文；不做像素 / 样式判断（ADR 0029）。
8. **注册表连带**：「视图 → 语言」是新组件，与 S1 同一 PR 登记（id 按 §14.3 流程在建单时
   报出确认，拟 `shell.menu.language`）。

## 代价与权衡

- **英文长文案 vs 紧凑密度**：「刷新」→「Refresh」长度近 4 倍，12px 紧凑档、定宽区
  （标签 180px、最紧窗口 960×640）大概率出现挤压。这是本决策最大的实做风险，逐区迁移的
  验收里必须带英文档 `--qa-layout-audit` 复跑。回应 ADR 0026 的论据：英文显著短于德 / 俄，
  且第一次有了用布局审计真量窄文案预算的机会，而不是靠估计维持"不做"。
- **锚点漂移**：各区代码被 catalog 包一层后行号整体平移，注册表 `frontend/...:行` 锚点会漂
  （编排技能坑 35）。每条迁移 Issue 的验收包含「用 `anchors.py` capture/apply 重算本区锚点」。
- **迁移是纯机械大宗改动**：Linux 2288 + Windows 795 候选（上限），分 5–6 个区 PR 消化；
  期间新增字符串一律直接走 catalog，混存状态是本 ADR 接受的过渡态。
- **中英混排是 v1 已知缺口**：后端错误在英文界面显示中文。发布说明必须如实写明，不留「已支持英文」
  的误导表述（AGENTS §13「未实现不得声称」同条精神）。
- 分类脚本按单行字符串字面量统计，多行 raw string 与拼接串未计入；UI 候选中还含内部显示码 /
  占位文本，真迁移数要人工再筛——「数字用于排期，不用于对账」。

## 重估条件

- **第三语言出现**：`zh* → 中文、其余 → English` 的映射必须重审；CLDR 复数与按语言字号下限
  同时回到台面。
- **热切换成为硬需求**（如系统语言变更跟随）：现方案按"重启生效"设计，界面构造期缓存文案的
  写法届时全部要改。
- **S8 决定改错误语义**：任何 `ErrorDetail` 形态变化都是契约变更，需要独立 ADR 与兼容性分析。
- **macOS 接入发版门禁**：`SUPPORTED_PLATFORMS` 扩容时本文的 sync/mark 口径随之生效。
