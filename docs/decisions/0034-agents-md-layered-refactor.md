# ADR 0034：AGENTS.md 分层重构与执行审批风险分级

- 状态：已接受（2026-11-18，维护者任务书直接授权）
- 日期：2026-11-18
- 关联：根 `AGENTS.md` 全文；新增 `backend/AGENTS.md`、`frontend/AGENTS.md`、
  `proto/AGENTS.md`、`docs/AGENTS.md`；[ADR 0025](0025-ui-behavior-contract.md)、
  [ADR 0027](0027-ui-component-registry.md)（注册表为 UI 行为真值——本 ADR 修正根文件中与之
  矛盾的过时表述）；[ADR 0029](0029-ui-acceptance-boundary.md)（UI 验收边界不变，其引用的
  「§15.0 改动确认单模板」机制自本 ADR 起被风险分级取代）；
  [ADR 0033](0033-sql-parser-readonly-policy.md)（其引用的「依赖引入确认单」语义由 §15.2 承接）。

## 背景

原根 `AGENTS.md` 669 行，问题：

1. 全局红线与 Driver SPI / gRPC / UI 模块细则混排，无关任务被迫加载全量上下文。
2. 同一规范在根文件与 `docs/` 专题文档两处维护，已发生漂移：根 §14.3 仍写「192 个组件、
   旧契约功能章节尚未退役、行为叙述以契约为准」，而契约自身与注册表实际状态（197 个组件、
   §1–§7 已迁为指针）相反——两处矛盾表述同时存在。
3. §15.0 要求任何写操作前先交「改动确认单」并等待「确认 #N」，阻碍已授权任务的自主执行。
4. §5 目录树与真实结构脱节（缺 `l10n/`、`tools/`、`dist/`），且文档树本身就是第二份易漂移副本。
5. §17（临时加入）对子 Agent 设了固定并发上限，与实际委派需求冲突。

## 备选方案

1. **保持单文件、纯删减**：上下文成本不降，模块细则仍全局加载。否决。
2. **重写并重新编号根文件**：代码注释（§6.2/§6.4/§8.1/§9/§10/§11）、活文档
   （§7/§8.6/§14.1/§14.2/§14.3/§14.4）、门禁脚本报错文案（§8.1/§14.4）按旧章节号引用，
   全部断链。否决。
3. **分层 + 章节号镜像**（采纳）：根保留 §1–§17 编号骨架与全局红线；细则迁至就近目录
   AGENTS.md 并镜像原章节号；专题文档仍是设计唯一真值。旧引用在根与模块两级都可解析。

## 决定

1. 根 `AGENTS.md` 精简为约 150 行：定位、技术栈与 IPC、产品/架构/Driver/契约/前端/安全/
   性能红线、测试与文档基线摘要（§14 保留为绑定摘要）、模块规范地图（§5）、执行策略（§15）、
   交接（§16）、委派（§17）。
2. 新建 `backend/AGENTS.md`、`frontend/AGENTS.md`、`proto/AGENTS.md`、`docs/AGENTS.md`，
   各承载对应根章节的完整细则。`frontend/<platform>/AGENTS.md` 暂不建立：平台规则目前较少，
   收在 frontend §8.2–8.4；某平台积累出独立长期规则后再单列（避免无谓文件增殖）。
3. **审批机制**：原 §15.0 逐次确认单硬门废止，替换为风险分级（根 §15）——授权范围内
   （实现、测试、直接关联文档、自引入故障修复、服务目标的局部重构）自主执行；超范围、
   架构重大调整、协议不兼容变更、生产/真实数据、不可逆操作、安全策略放宽、新大型依赖
   仍需先确认。Git 纪律收紧保留：不破坏性操作、不覆盖未提交改动、不擅自提交推送。
4. **委派机制**（根 §17）：不设固定并发配额；按复杂度、上下文成本、并行收益与文件冲突
   风险决定；同文件不并发修改；子 Agent 结论视自称处理，外部副作用由主 Agent 回读验证。
5. **冲突裁决**：UI 行为真值唯一为组件注册表（契约仅全局规则 + 已知偏差），删除根内
   过时叙述与写死的组件计数；§14.3/§14.4 发版门禁与全部检查脚本约束原样保留并明确
   「任何重构授权不构成绕过理由」。
6. 同步更新 `.github/pull_request_template.md`（「改动确认」节 → 「执行授权」节）与
   `CONTRIBUTING.md` 的阅读入口表述。

## 后果

- (+) 无关任务的指令上下文降到约四分之一；细则只在一处维护，根与模块镜像编号使既有
  引用全部可解析；已授权任务可连续执行。
- (−) 模块细则依赖 Agent 主动读取：以根 §5 地图、「读过才算存在」条款与 PR 模板核对项
  对冲；跨模块任务需读多份文件，属可接受的人工成本。
- 历史 ADR 中的旧章节引用（如 §15.0 确认单）作为当时事实保留，不回改（追加式原则）。
- 重新评估条件：若某模块细则在评审中反复因「没读到」被违反，则该条上移根文件；若根文件
  再次超过约 180 行，重复本流程再拆。
