# v0.2.1 发布说明

- 状态：**已完成**（2026-11-05，Linux 验证）。三个退出标准都有可执行证据，逐条见
  [发布计划](../planning/release-plan.md#v021)；性能数字来自 **debug** 构建，Windows / macOS
  前端未构建、未验证——见「已知限制」。
- 覆盖里程碑：M4 元数据与事务（已完成，任务 #41–#48 / PR #50–#57）。
- 范围：Linux 前端（GTK4 + libadwaita）+ 本地后端 + SQLite / MariaDB 驱动。
- 证据基线：main `47da472`（其后只有本发布说明相关的文档提交 `3796915`，未改任何代码）。

## 概览

v0.2.1 把「看数据、改数据」做成可用闭环。后端为两个驱动补齐显式事务与元数据最小子集，
新增 `TableDataService`（按主键升序的不透明游标浏览 + 参数化行编辑）；Linux 前端新增数据页：
左侧表/视图列表、虚拟化网格、单元格编辑与 NULL 开关、脏行标记、风险确认、事务状态
（四态；v0.2.3.3 起无常驻徽标）。

行变更走「主键值 + 列变更」的强类型请求，驱动内部用 prepared statement 绑定参数，通用层与
前端都不拼接 SQL（ADR 0017）。

**它仍不是完整的数据库客户端**：只有 Linux 有可用界面；**不能插入新行**；没有对象树全量、
没有 DDL 查看、没有导入导出；排序只有主键升序。PostgreSQL 与 Windows/macOS 前端不可用。

## 行为变化

1. **新服务**：proto 新增 `proto/services/v1/table_data.proto`（`TableDataService`），
   后端域服务从 6 个变为 7 个。`MetadataService` 追加 `GetPrimaryKey`，
   `TransactionService` 的三个 RPC 不再返回 `UNIMPLEMENTED`。
2. **proto 只做增量**：`metadata.proto` 追加 `GetPrimaryKeyRequest` / `GetPrimaryKeyResponse`；
   `transaction.proto` 追加 `TransactionInfo.state = 5`、`enum TransactionState`、
   `message TransactionStatus`；`connection.proto` 追加 `SessionSummary.transaction = 7`。
   没有字段号复用、删除或改语义，旧客户端忽略未知字段与服务即可。
3. **`ListSessions` 带事务快照**：会话有打开事务时 `SessionSummary.transaction` 给出
   事务 ID、隔离级别、只读标志与状态；无事务时该字段缺省（旧客户端行为不变）。
4. **能力描述符**：两个驱动的 `transactions` 变为 `true`（`ListDrivers` 可见变化）。
   表数据/行编辑能力**没有**加进 `Capabilities`（新增字段会破坏两个驱动现有的穷举字面量），
   因此 `ListDrivers` 不展示这两项；调用方以 `TableDataService` 的错误语义为准。
5. **新错误码 9 个**（见下表）。它们都是**新增**，既有错误码语义未变。
6. **断连语义**：显式 `Disconnect` 与后端退出会强制回滚打开的事务；后端退出日志记录
   `会话清理已强制回滚打开的事务 transaction=… reason="后端退出"`。
7. **前端主区域**：连接后主区域显示「表与视图」列表，点击条目进入数据页；右上「SQL 工作区」
   切回编辑器。两个页面共用同一个数据库会话，SQL 工作区的查询仍是 `auto_commit=true`。
8. **无人值守验证参数**：新增 `--qa-data-table` / `--qa-data-begin-txn` / `--qa-data-read-only` /
   `--qa-data-edit` / `--qa-data-delete-row` / `--qa-data-scroll-to-row` / `--qa-data-commit` /
   `--qa-data-rollback` / `--qa-data-reload`（详见 `frontend/linux/README.md`）。

### 新增错误码

| 错误码 | 触发条件 | 客户端处理建议 |
|---|---|---|
| `table_data.no_primary_key` | 目标表/视图没有主键，无法稳定定位行 | 显示只读原因，禁用编辑；不尝试 rowid/ctid 近似定位 |
| `table_data.read_only` | 目标只读（视图、驱动只读模式，或驱动未声明行编辑） | 同上，按原因文案提示 |
| `table_data.cursor_invalid` | 浏览游标非法、被篡改或与表/排序不匹配 | 停止翻页并重新从第一页开始，**不要**把游标当页码解析 |
| `table_data.rows_affected_mismatch` | 整批影响行数与期望不符 | 提示并发冲突，重新浏览后再改 |
| `table_data.row_deleted` | 目标行已被其它会话删除 | 标记该行失效，重新加载 |
| `table_data.confirmation_required` | 预计影响行数超过风险阈值但请求未带确认 | 弹出确认对话框，用户确认后重发 |
| `table_data.truncated_value` | 提交的单元格值是被截断的前缀 | 拒绝写入并提示「查看完整值」不可用（本版未实现） |
| `transaction.not_found` | 事务 ID 不存在或已结束（例如对已提交事务提交行变更） | 重新 `Begin`；绝不退化成自动提交 |
| `transaction.already_active` | 会话已有打开的事务时再次 `Begin` | 复用现有事务或先提交/回滚 |

逐行结果另有两个非错误码的 `ChangeOutcome`：`Conflict`（影响行数不符）与
`RowNotFound`（目标行不存在），它们出现在 `ApplyRowChanges` 的逐行报告里，整批仍可继续。

## 已知限制

以下条目都**不可用或未验证**，界面与文档不得把它们呈现为已支持：

1. **Windows / macOS 前端**：只有窗口骨架，未接后端、未构建、未运行验证、未在 CI 覆盖。
2. **不能插入新行**：数据页只有编辑与删除；`INSERT` 计划 v0.2.2。
3. **对象树只有一层**：当前库的表/视图；Catalog / Schema / Index / Sequence 与跨库浏览返回
   `capability.unsupported`；没有 DDL 查看（v0.2.2）；前端是平铺列表，不是可折叠树。
4. **排序只有主键升序**：不能按其它列排序，也不能反向；`page_token` 只能向前推进。
5. **无主键表/视图只读**：浏览可用，编辑一律拒绝，不提供近似行定位。
6. **前端进程崩溃不触发自动回滚**：gRPC 流断开与会话解耦，崩溃不会走到 `Disconnect`；
   会话只在显式 `Disconnect` 或后端退出时清理，这两条路径会强制回滚（后端退出已实测）。
7. **SQL 工作区与数据页的事务不联动**：手写 `BEGIN` 后数据页徽标不会即时刷新，
   此时数据页写入会被服务端 `transaction.already_active` 拒绝。
8. **UI 层未逐项 e2e**：逐行失败面板（`ROW_NOT_FOUND` / `CONFLICT`）只有单元测试；
   事务「失败态」徽标未用 e2e 触发；截断列禁编只有代码判定 + 单元测试；
   数据页 Loading / Empty / Error 三态未逐态截图。
9. **截断值不可编辑**：`truncated=true` 的单元格不进入编辑态，「查看完整值」未实现。
10. **单批 500 行**：超过时返回 `clamped` / `deferred_changes`，界面提示再次提交，不静默丢弃。
11. **隔离级别无 UI**：界面只提供「只读」开关；MariaDB 支持四档隔离级别（`Snapshot` 拒绝），
    SQLite 只接受 `Serializable`。savepoint 只在行编辑批次内部使用。
12. **元数据字段不全**：`ColumnMeta` 没有默认值、字符集、排序规则字段（契约冻结），
    驱动能读到但传不到前端；`ENUM` / `SET` / `GEOMETRY` / `BIT` 以 `Unsupported` 保留原文。
13. **大库元数据一次性读入**：一次请求读取当前库全部对象名再在内存切页（每页 ≤ 500），
    对象极多时应改为服务端游标（待定）。
14. **只有 debug 构建的性能观察**：10 万行翻页（每页 500 行、200 页）SQLite 100.8 ms、
    MariaDB 499.0 ms，release 构建未测量；这是同机观察值，**不是发布承诺**。
15. **真实 TLS、MySQL 8.x、MariaDB < 10.6 未验证**：TLS 只有模式映射与参数校验的单元测试，
    测试容器未启用 TLS。
16. **版本号未提升**：后端 workspace 版本与 `GetVersion` 的 `service_version` 仍是 `0.1.0`，
    不要用版本字符串判断是否 v0.2.1。

## 升级注意

- **proto 兼容**：本版只有追加——新文件 `table_data.proto`、`GetPrimaryKey` 两个消息、
  `TransactionInfo.state`、`TransactionState`、`TransactionStatus`、`SessionSummary.transaction`。
  没有字段号复用、删除或 `reserved` 变更；按 v0.2 契约实现的客户端连接 v0.2.1 后端不会报错，
  只是看不到新能力。
- **`TransactionService` 从「未实现」变为可用**：以前调用得到 `UNIMPLEMENTED` 的客户端现在
  会真正开启事务；若客户端把 `UNIMPLEMENTED` 当作「安全降级」信号，需要改为按能力描述符
  `transactions=true` 判断。
- **`Begin` 可能返回 `transaction.already_active`**：一个会话同时只有一个事务。数据页与
  SQL 工作区共用会话时，两边的写入可能互相看到这个错误——先提交或回滚再操作。
- **新增错误码需要兜底**：旧客户端遇到未知 `error_code` 时应按 gRPC 状态码与消息展示，
  不要把未知 code 当成成功或静默重试。完整清单见上表。
- **无配置迁移**：`connections.json` 格式、端点文件字段、`protocol_version`（仍是 `v1`）
  都没有变化；不需要清理任何本地文件。
- **数据安全**：行编辑是真实 DML。默认在 > 100 行或含删除时要求确认；建议在显式事务里操作
  大批量修改，并在提交前用「放弃更改」核对。删除无法通过本界面撤销。
- **版本号**：`service_version` 仍是 `0.1.0`，请用本文与支持矩阵判断能力。
