# v0.2.3 发布说明

- 版本主题：**工作区 UI 重构**（M7）
- 覆盖范围：Linux 前端（GTK4 + libadwaita）+ 本地后端 + SQLite / MariaDB 两驱动
- 证据基线：代码 `a74ca8f`（其后只追加本发布说明与需求/计划同步提交，不改行为）
- 上一版本：[v0.2.2](v0.2.2.md)

## 概览

v0.2.3 把界面从「一窗口 · 一会话 · 一页面」改成**多连接 · 多标签 · 表格为中心**，
并把表浏览从「固定主键升序 + 滚动到底自动取页」改成**可选排序/筛选 + offset 分页 + 总数三态**。
契约侧只做增量：`BrowseTable` 追加 offset / 排序 / 筛选 / 总数 / 计数超时，旧客户端行为不变。

界面结构与决策已固化为文档：`docs/ui-specification/workspace-model.md`、
ADR 0021（标签与会话）、ADR 0022（分页、排序、筛选、总数；含 2026-11-07 采纳的计数有界超时修订）、
ADR 0023（三端区域一致 + 原生控件）。

## 行为变化（可见 / 需注意）

1. **滚动到底不再自动取下一页**：改由分页器（首页/上页/下页/末页，页码只读）驱动，翻页后回到顶部。
2. **排序/筛选会重置到第 1 页**，且请求只带 `offset` 不带 `page_token`（驱动拒绝二者并用）。
3. **总数有三种口径**：精确「共 N 行」、估计「约 N 行」、超时/未请求时「未统计」；不再只有一种数字。
4. **表数据工具条改为两行**（事务控制 / 行变更），因为 960 宽下一行放不下且会重叠。
5. **标签条高度 47px**（`AdwTabBar` 实测，规范原型画的是 24）。
6. **导出范围是「已加载」而不是全部**：查询结果导已加载行（不重跑 SQL），表数据导当前页；确认对话框与完成提示都写明。
7. **连接入口从 headerbar 移到主工具条**（headerbar 只留标题与菜单）。
8. **`Objects` 固定页仍是占位说明**（对象概览未实现，见 #135），文案已改成如实标注。

## 升级注意

- **proto 只追加**：`BrowseTableRequest` 的 4–7 与 10、`BrowseTableResponse` 的 8–9 与 11 是新字段，旧字段号与语义未变；不填新字段的旧客户端行为与 v0.2.2 完全一致。
- **能力位**：`table_browse_sort_filter_total` 在两个内置驱动为 `true`；前端据此显示排序/筛选/总数入口，为 false 的驱动不显示（有单测）。
- **ADR 0022 已修订**：精确计数由「可取消、有超时」改为「有界超时 + 服务端中断」（2026-11-07 采纳方案 A）；客户端取消明确不在本版。
- **配置文件不会自动迁移**：`connections.json` 里可能已积累重复条目。本次发布前后已协助把本机 142 条清到 13 条（每目标留最新一条，备份为 `connections.json.bak-*`）；被删条目在系统密钥环里的密码条目未清理（可通过 `DeleteCredential` 逐个删）。
- **QA 会隔离配置**：验收脚本把 `XDG_CONFIG_HOME` 指到临时目录并断言真实配置条目数不变；手工跑 `--qa-*` 时仍会写真实配置，需要注意。

## 性能与规模观察（非承诺）

- MariaDB 15 万行表：`offset=0` ≈2 ms、`offset=90000` 7.4–16.7 ms（同机观察值）。
- MariaDB 25 万行表：总数走 `information_schema.TABLES.TABLE_ROWS` → `约 250149 行`（真值 25 万，误差 <0.1%，但仍是估计值）。
- 视图交叉连接 1000×1000：计数 1 ms 预算内必然超时 → 「未统计」，分页与取页不受影响。
- CSV 导出 10 万行：0.418 s、7.4 MB、峰值 RSS 增量 824 KiB（逐行写，不整份入内存）。
