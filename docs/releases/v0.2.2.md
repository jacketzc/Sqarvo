# v0.2.2 发布说明

- 状态：**已完成**（2026-11-06，Linux 验证）。五条退出标准都有可执行证据，逐条见
  [发布计划](../planning/release-plan.md#v022)；Windows / macOS 前端未构建、未验证，TLS 与
  release 构建的性能基准未测量——见「已知限制」与「未验证项」。
- 覆盖里程碑：M4 元数据与事务（v0.2.2 收尾：对象树、DDL、搜索）。
- 范围：Linux 前端（GTK4 + libadwaita）+ 本地后端 + SQLite / MariaDB 驱动。
- 证据基线：main `ca0df3c`（`9f3d2ce` 之后合入三个发布前修正：`9f7fec8`、`43a18e5`、`ca0df3c`，均为注释或测试稳定性，不改协议字段与错误码语义）。

## 概览

v0.2.2 把「浏览数据库对象」做成可用闭环。后端把元数据从「当前库表/视图 + 列」扩展到
Catalog（SQLite 的 database / MariaDB 的 database）→ 表/视图/序列 → 列/索引/触发器 的逐层懒加载，
新增 DDL 原文读取（`GetDdl`，标注是否原文并纳入会话执行锁）、对象搜索（名称过滤下推到数据库）
与插入新行（`InsertRows`，自增/默认值/唯一冲突/整批原子）。Linux 前端新增可折叠对象树、
搜索跳转、DDL 面板、插入行与事务隔离级别入口，并在提交行变更时支持取消提交。

**它仍不是完整的数据库客户端**：只有 Linux 有可用界面；没有导入导出、没有结构对比/ER 图；
PostgreSQL 与 Windows/macOS 前端不可用；排序只有主键升序；跨库只支持元数据浏览，不支持
跨库表数据读写。搜索的大小写/重音行为跟随数据库，三个能力（自增列标志、按主键单行回读、
插入批次取消）仍受契约限制。

## 行为变化

1. **子节点顺序**：从 v0.2.1 的「只按名字」改为先按种类（`ObjectKind` 声明顺序）、再按名字。
   视图排在所有表之后；依赖全局字母序的客户端/脚本需要更新。前端不重排，直接按服务端顺序渲染。
2. **`GetDdl` 的来源语义**：新增 `source` / `source_detail` / `generator_version`，
   不变式是 `exact == (source == DDL_SOURCE_DATABASE)`；拼装却说不清来源/版本的结果会被
   rpc-server 以 `internal.error` 拒绝。本版两个驱动都只返回原文，因此 `exact` 恒为 `true`；
   拿不到原文的对象（SQLite 隐式索引、MariaDB 索引/触发器）返回明确错误码，不返回空串或伪造 DDL。
3. **插入批次整批原子**：单行失败不中断其余行的执行（为了报全失败），但最终整批回滚，
   `rolled_back=true`、`total_rows_affected=0`；逐行结果仍返回。前端只认 `rolled_back`，
   不把「语句成功 N 行」当成功。
4. **取消提交语义**：行变更批次可携带前端生成的 `query_<uuid>`；取消在行边界生效，
   已执行的语句随整批回滚，脏行保留可重试；无进度推送，`InsertRows` 批次本版不可取消。
5. **`ListNodes.filter` 不再是「未实现」**：rpc-server 把非空过滤接到 SPI 的
   `list_children_filtered`；结构非法的过滤 `metadata.filter_invalid`，未实现下推的驱动
   `UNIMPLEMENTED` + `capability.unsupported`（不静默返回未过滤列表）。两个内置驱动已下推。
6. **能力描述**：两个驱动的 `catalogs` 改为 `true`（`schemas` 仍 `false`）；`row_editing`
   涵盖插入。`ddl_generation` 仍为 `false`——驱动不生成/拼装 DDL，只返回数据库原文。
7. **Linux 前端导航**：连接后左侧默认是可折叠对象树；v0.2.1 的平铺表列表保留为可切换视图
   （侧栏「平铺列表」/「DDL」按钮）。数据页、SQL 工作区、连接与凭据路径不变。
8. **无人值守参数新增**：`--qa-tree-*`、`--qa-expect-tree`、`--qa-expect-ddl`、
   `--qa-column-info`、`--qa-expect-column`、`--qa-data-insert*`、`--qa-data-cancel-after-ms`、
   `--qa-isolation-dialog`、`--qa-isolation-level`、`--qa-isolation-confirm`（详见
   `frontend/linux/README.md`）。

### 新增错误码

| 错误码 | gRPC 状态码 | 触发条件 | 客户端处理建议 |
|---|---|---|---|
| `metadata.object_not_found` | `NOT_FOUND` | 目标表/视图/索引/库不存在 | 重新加载对应层级，不要当成空列表 |
| `metadata.object_kind_unsupported` | `INVALID_ARGUMENT` | 对象种类不能用于该操作（对列取 DDL、展开叶子、MariaDB 索引/触发器取 DDL） | 隐藏该入口或解释「该对象没有独立 DDL」 |
| `metadata.permission_denied` | `PERMISSION_DENIED` | 数据库拒绝读取元数据（`information_schema` 不可见） | 提示权限不足，不降级成「不存在」 |
| `metadata.filter_invalid` | `INVALID_ARGUMENT` | 过滤条件非法（`contains`/`exact` 同时给、匹配串为空、`kinds` 重复或含 `UNSPECIFIED`） | 修正过滤条件后重搜，不重试同一请求 |
| `table_data.unique_violation` | `ALREADY_EXISTS` | 插入违反主键/唯一约束（逐行，不中断整批） | 标出冲突行；整批 `rolled_back=true` 时不要重试原批次 |
| `table_data.not_null_violation` | `INVALID_ARGUMENT` | 显式 NULL 写进 NOT NULL 列 | 去掉该列或改值 |
| `table_data.not_null_without_default` | `INVALID_ARGUMENT` | 省略 NOT NULL 列且该列没有默认值 | 补一个值（与上一条处置不同，不能合并提示） |
| `table_data.column_not_insertable` | `INVALID_ARGUMENT` | 列由数据库生成（`GENERATED ALWAYS` / 计算列） | 从插入列里移除；普通 `AUTO_INCREMENT` 不在此列 |
| `table_data.permission_denied` | `PERMISSION_DENIED` | 缺少 INSERT 权限（整批失败） | 提示权限不足，不重试 |

「逐行失败」与「整批失败」的分工：插入的逐行错误在 `InsertRowResult.error_code`（响应内）；
只有整批无法执行（无权限、对象不存在、事务不存在、驱动未实现）才用 `Err` 返回上面的码。

## 已知限制

以下条目都**不可用或未验证**，界面与文档不得把它们呈现为已支持：

1. **Windows / macOS 前端**：只有窗口骨架，未接后端、未构建、未运行验证、未在 CI 覆盖。
2. **schema 层不存在于两个内置驱动**：SQLite / MariaDB 没有独立 schema，请求 schema 一律
   `capability.unsupported`；PostgreSQL 驱动未实现，因此没有 schema 层的正例证据。
3. **MariaDB 索引/触发器 DDL 不可用**：`ObjectRef` 不携带所属表，无法唯一定位索引；
   报 `metadata.object_kind_unsupported`，不拼装。要看索引定义请查看所属表的 `SHOW CREATE TABLE`。
4. **DDL 不截断**：超过 gRPC 消息上限（tonic 默认 4 MiB）时请求失败；没有 `metadata.ddl_too_large`
   这类业务错误码。
5. **搜索的大小写/重音跟随数据库**：`contains` 与 `exact` 不对称（`LIKE` 与 `=`），SQLite 只折叠
   ASCII，MariaDB 的 `LIKE` 连重音一起折叠；不提供 `case_sensitive` 开关。`NO_BACKSLASH_ESCAPES`
   打开时 MariaDB 的默认转义符失效，本版不处理。
6. **前端搜索范围**：只查当前库根层，只展示首页 500 条；不做跨层/跨库搜索，更多结果需换关键词
   或逐层展开。
7. **自增列标志缺失**：`ColumnMeta` 没有 `auto_increment`（也没有 generated/identity），
   MariaDB 的自增列在元数据里与「不可空 + 无默认值」完全一样；UI 只能默认「省略」并说明，
   **无法禁止**用户显式填写自增值。
8. **插入后不回读省略列**：没有「按主键回读单行」的 RPC，成功行里 `id` 之后的值显示
   「数据库生成」，要看真实值必须刷新（整表重读第一页）。
9. **插入批次不可取消**：`InsertRowsRequest` 没有 `query_id`；行变更批次可取消，插入不行。
10. **跨库只读**：元数据可跨库，`BrowseTable` / 行编辑 / 插入仍只作用于当前库。
11. **对象树不自动刷新**：折叠后重新展开复用已加载页；数据变化需点侧栏「刷新」。
    容器 `has_children=true` 但实际 0 个子节点时，箭头不会自动消失。
12. **搜索/插入的 UI 闭环只在 SQLite 上复跑**：MariaDB 的 UI 证据本轮只覆盖对象树与 DDL；
    MariaDB 的插入/DDL 语义由驱动与 gRPC 测试覆盖。
13. **截图是 GTK 自渲染**：Wayland 下不是 OS 级截屏，也没有真实指针注入；列头点击走控件几何
    与同一处理函数，列宽拖拽只验证「手势不抢」。
14. **无权限的真实前端场景未跑**：测试账号权限过全，`metadata.permission_denied` 只有前端文案
    单测与驱动集成用例（MariaDB 侧读 `mysql` 库）。
15. **取消提交的端到端证据来自 #89**：本轮未重跑 500 行 + 慢触发器的场景；其日志显示
    `CancelRowChanges` 往返 1 ms、`已执行 128 条`、外部 SQL 0 行变化。
16. **SQL 工作区与数据页的事务不联动**：查询仍是 `auto_commit=true`；手写 `BEGIN` 后数据页徽标
    不即时刷新，数据页写入会被 `transaction.already_active` 拒绝。
17. **排序与分页**：只有主键升序；`page_token` 只能向前推进。
18. **性能数字不是承诺**：SQLite 10 万对象搜索 9.3 ms、MariaDB 1 万对象 7.2 ms 来自 #84 的
    release `#[ignore]` 基准；MariaDB 10 万对象未实测。启动/内存/大结果集仍只有 debug 构建数值。
19. **版本号未提升**：后端 workspace 版本与 `GetVersion` 的 `service_version` 仍是 `0.1.0`，
    不要用版本字符串判断是否 v0.2.2。

## 升级注意

- **proto 兼容**：本版只有追加——`ListNodesRequest.filter = 3`、`GetDdlResponse.source = 3` /
  `source_detail = 4` / `generator_version = 5`、`TableDataService.InsertRows`（追加在末尾）与
  相关 message。既有字段号未动、未删除、未复用；按 v0.2.1 契约实现的客户端连接 v0.2.2 后端
  不会报错，只是看不到新能力。
- **子节点排序变化是对外可见行为**：升级后 `ListNodes` 的返回顺序不再保证全局字母序。
  如果客户端缓存或对顺序做假设，需要改为按（种类, 名字）或直接使用服务端顺序。
- **`GetDdl` 从「未实现」变为可用**：以前得到 `UNIMPLEMENTED` 的调用现在会返回原文；
  请按 `exact` / `source` 判断来源，不要把 `source=UNSPECIFIED` 当作原文。
- **`ListNodes.filter` 从「非空即拒」变为下推**：旧客户端如果依赖「传 filter 就报
  `capability.unsupported`」来探测版本，需要改为检查能力描述或直接使用过滤。
