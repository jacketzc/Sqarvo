# v0.2.3.1 发布说明

- 版本主题：**M6 前端硬化（第一批）**
- 覆盖范围：Linux 前端（GTK4 + libadwaita）+ 本地后端；无协议变更
- 上一版本：[v0.2.3](v0.2.3.md)

  信号退出留孤儿后端）全部关闭，并补上「点已保存连接 = 直接连接」的交互缺口。

## 行为变化（可见 / 需注意）

1. **保存同一目标不再追加**：身份键 = 驱动 + 主机（大小写不敏感）+ 端口 + 用户名 + 库；
   SQLite = 驱动 + 规范化绝对路径（`./a.db`、`a.db` 与大小写差异视为同一文件）。再次保存
   更新名称 / TLS 等字段，密码覆盖原引用指向的密钥，配置与密钥环都不再堆条目。
   加载旧配置时已有的重复条目按同一规则合并并记一行日志（保留最近一次保存的那条）。
2. **启动态侧栏点击语义改为「直接连接」**：点一条已保存连接即按保存的凭据建立浏览会话，
   成功后落到工作区并在树里展开该连接；编辑 / 删除 / 断开移到右键菜单。凭据缺失时提示
   「这条连接缺少密码」并打开预填对话框，不静默失败。
3. **信号退出不再留孤儿后端**：`SIGTERM` / `SIGINT` / `SIGHUP` 走与关窗口相同的清理路径；
   前端被 `SIGKILL` 时，后端凭 `--parent-pid`（仅前端启动时传入）的 `PR_SET_PDEATHSIG`
   与 500 ms 轮询自行退出。手工启动的后端不带该参数，不会被误杀。
4. **CSV 导出默认转义公式前缀**：文本类值以 `=`、`+`、`-`、`@`、制表符、回车开头时前置
   单引号；数值类（含 `-5`）保持原样，避免改变数值语义。确认对话框里的开关可关闭。
   文件含被服务端截断的单元格时，末尾追加一行 `# sqarvo: …` 注释（不改变列数）。
5. **数据列宽可拖拽**：第二行类型条带跟随列宽；列被隐藏时类型格一并收起；双击列边界按
   内容自适应。宽表（7 列以上）不再挤压信息面板。
6. **`Objects` 固定页有内容**：对象名 / 种类 / 限定名 / 关键属性 3–5 项，与右侧信息面板
   同一份快照；无选中时是空状态说明，不摆占位数据。

## 已知限制（更新）

| 限制 | 状态 |
|---|---|
| 数据列宽不可拖拽 | **已修复**（#133） |
| `Objects` 页无对象概览 | **已修复**（#135） |
| 导出 CSV 未转义公式前缀；截断值无标记 | **已修复**（#137）；标记为文件末尾注释行，消费者需忽略以 `#` 开头的行 |
| 宽表把信息面板压到 ~198px | **已修复**（#133，类型条带不再参与最小宽度传播） |
| 同一目标重复保存会新增配置条目 | **已修复**（#145）；旧重复条目加载时合并，被合并条目的密钥环残留不自动回收 |
| MariaDB 筛选/排序未做值类型预校验 | 仍存在，后续版本定口径 |
| `ESTIMATE` 下「末页」可能与真实末页差一两页 | 已知口径 |
| 客户端取消表浏览计数不可用（一元 RPC 无取消通道） | ADR 0022 修订记录 |
| 只有 Linux 前端；Windows / macOS 仍是窗口骨架 | M6 剩余条件 |

## 验证记录

```bash
cd backend && cargo fmt --all -- --check && cargo clippy --all-targets -- -D warnings
SQARVO_MARIADB_URL=… cargo test --workspace        # 640 passed / 0 failed / 2 ignored
cd frontend/linux && cargo fmt --all -- --check && cargo clippy --all-targets -- -D warnings
cargo test                                         # 356 passed / 0 failed / 1 ignored
SQARVO_QA_PASSWORD=… ./scripts/v023-acceptance.sh  # 139 项断言全过（54 应用内 + 85 脚本）
```

- **#145**：真机连续两次保存同一 MariaDB 目标 → `connections.json` 1 条、`credential_ref`
  两次相同，Secret Service 按该引用只检索到 1 个条目；反证「改回按引用匹配」→ 3 条用例变红。
- **#144**：`--qa-startup-click` 断言「`Connect` 恰好 1 次、`ListSessions` 1 条浏览会话、
  树上该连接已展开」；凭据缺失与空引用两条路径都给出提示并打开预填对话框。
- **#146**：`kill -TERM` 前端 109 ms 退出、后端约 50 ms 消失且端点文件删除；`kill -KILL`
  前端后后端约 50 ms 自行退出；手工启动的后端（无 `--parent-pid`）在启动 shell 退出后仍在运行。
- **#137**：六类危险前缀单测；导出原文 `1,'=1+1,-5,…`、`5,"'\tfoo"`、`6,"'\rfoo"`；
  截断文件末尾出现 `# sqarvo: 本文件含 1 个被截断的单元格…`；关闭开关后写原始值。
- **#133**：列宽断言（类型格分配宽 == 列宽 ±1 px）在 1200×800 与 960×640 两档 0 超限；
  反证「去掉 `notify::fixed-width`」→ 断言失败（exit 3）。
- **#135**：连接 / 库 / 表 / 列四张截图与信息面板同值；布局自检 1200×800、960×640 各 15 项
  0 超限；反证「改了 Objects 标题」→ 断言报「页面与快照不一致」。

证据目录（仓库外）：`/home/jack/sqarvo-v023-shots/{145,144,146,137,133,135}/`，以及
`main-*` 的验收链目录。

## 未验证项（如实标注）

- **Windows / macOS 前端**：仍是窗口骨架，未接后端、未构建、未验证（M6 剩余条件）。
- **release 构建**的本轮性能与验收链未复跑（全部为 debug 构建）。
- **LibreOffice 往返复核未跑通**：本机 `soffice --headless --convert-to csv` 对任何输入都报
  `source file could not be loaded`；公式前缀结论以 CSV 原文与单测为准，已在 PR #150 标注。
- 旧重复条目被合并后，其密钥环条目不会自动回收（无法判断是否被其他配置引用）。
- MariaDB 筛选/排序的类型不兼容路径、`NO_BACKSLASH_ESCAPES` 场景仍未验证。
