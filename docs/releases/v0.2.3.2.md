# v0.2.3.2 发布说明（前端增量）

- 版本主题：**界面逻辑收敛与整表导出**（M6 前端接入与硬化）
- 版本定位：v0.2.3 的**第二个增量补丁**，接在 [v0.2.3.1](v0.2.3.1.md) 之后；前端增量按仓库约定用
  四段号 `v0.x.x.x`，不占用 `v0.2.4`（那个号仍留给三端/三驱动版本）
- 覆盖范围：Linux 前端（GTK4 + libadwaita）+ 文档；**无协议变更**（`proto/` 未改动）
- 证据基线：代码 `1abbce7`（其后只有文档提交：本发布说明、ADR 0022 增量节、改标与 Issue #154 登记，不改行为）
- 上一版本：[v0.2.3](v0.2.3.md) 与其增量 [v0.2.3.1](v0.2.3.1.md)

## 概览

`v0.2.4` 是 roadmap 里的三端/三驱动版本（Windows / macOS 接入、PostgreSQL 驱动、性能与安全验收、
打包），**不是「首个完整可用版本」**，也不由本增量兑现。本说明只覆盖其中**Linux 前端的一次逻辑收敛**。

这次改的不是外观，而是**行为口径**：把「点一下就把表打开」「右键菜单里塞 DDL」「信息面板可折叠」
「后端失效时给一个『断开后端』按钮」这些只在 GTK 实现里成立的交互收掉，换成单入口、常驻面板与
面向用户的恢复路径；同时给表数据的 `EX` 补上「整张表」范围——不新增 RPC、不动 proto，靠 offset
逐页 `BrowseTable` + 流式写同一个 CSV 实现（决策见 ADR 0022 新增的「v0.2.3.2」一节）。

编号说明：这批改动最初在 `646c824` 里以 `v0.2.4` 命名发布，2026-11-08 按「前端增量用四段号」的
约定改为 `v0.2.3.2`；`v0.2.4` 的编号与范围不变。历史提交不重写。

跟踪：#154（M6）。

## 行为变化与升级注意

1. **单击不再打开表**：单击只选中并更新信息面板 / `Objects` 页，双击或回车才激活。
   键盘用户与旧验收脚本都要走激活动作。（本版修正了「表有四组子节点后双击只展开、
   不打开」的回归，见「新增能力」最后两行。）
2. **右键只剩「打开」**：**「查看 DDL」已移除**，DDL 在信息面板的 `[DDL]` 页看；同时删除
   侧栏平铺列表、页脚 DDL 按钮与分页统计行。
3. **三处「断开后端」入口移除**：后端失效时只给「重启 Sqarvo」与「查看日志」两种恢复方式。
   日志文件是 `$XDG_STATE_HOME/sqarvo/desktop.log`（默认 `~/.local/state/sqarvo/desktop.log`），
   从终端启动时 stderr 里仍有同样的输出。
4. **信息面板常驻**：没有折叠按钮，也没有 `Ctrl+I`；默认宽 280，窗口级记忆（#155 起；旧版按连接记录会在首次读取时迁移），首帧不再把
   240（分栏下限）误记成用户选择。
5. **事务行没有「自动提交」徽标**：未开事务时该行只显示「开始事务」；开始后按钮换为
   提交 / 回滚，两者互斥。
6. **行变更按钮改短标签**：`提交（N）` / `撤销` / `删除` / `新增`（960 宽下原长标签会挤出工具条）。
7. **状态栏与工具条的行操作变成图标**：`FS` / `CC` / `EX` 等按钮只留图标，语义在 tooltip 与
   可访问名里；纯靠视觉找按钮的老用户可以按快捷键（`Ctrl+Shift+E` 导出等）。
8. **`EX` 先选范围**：表数据导出默认仍是「当前页」，整张表是显式动作；整表读的是数据库里
   **已提交**的值，本页未提交的编辑不在文件中（确认框写明）。
9. **`window.json` 旧宽度会迁移**：旧版按连接存的 `inspector_width` 在首次读取时取最常用的值
   作为窗口级宽度（#155），首次拖拽后写回 `last_inspector_width` 并清空旧表；没有 proto 变更，
   旧客户端与新客户端互不影响。

## 已知限制

| 限制 | 说明 / 去向 |
|---|---|
| `Foreign Keys` 只是占位 | 驱动 SPI 无外键列表能力，节点显示 `capability.unsupported`、不发 RPC；需后端先补能力 |
| 整表导出的取消粒度是**页边界** | 取消位在每个 RPC 前与每行之间检查；单页 RPC 在飞时要等这一页返回（最多 500 行）。与 ADR 0018 的行变更取消同源，见 ADR 0022 增量节 |
| 日志文件**无轮转** | `desktop.log` 只追加、不截断，长期运行会持续增长；需要按大小/日期轮转 |
| 硬杀进程时导出临时文件可能残留 | `SIGKILL` 来不及走 `CsvSink` 的 `Drop`，目标同目录会留下隐藏的 `*.sqarvo-tmp` |
| `Objects` 页「加载更多…」无 QA 入口 | 该按钮不在 GAction 里，无人值守点不到；`v0232` 脚本只断言「共 N 个对象」且日志没有「还有更多」 |
| 整表导出缺少 MariaDB 自动化 | `v0232-objects-export.sh` 用自包含 SQLite 夹具；MariaDB 上的整表路径本轮未进脚本 |
| 只有 Linux 前端；Windows / macOS 仍是窗口骨架 | M6 剩余条件 |

## 未验证项（如实标注）

- **Windows / macOS 前端**：仍是窗口骨架，未接后端、未构建、未验证（M6 剩余条件）。
- **release 构建**：本轮全部为 debug 构建，release 的启动、内存与验收链未复跑。
- **整表导出的性能**：本版没有新增基准；10 万行 CSV 的吞吐数字仍是 v0.2.3 对「导出当前页/查询结果」
  的观察值，不能直接搬到「每 500 行一次 `BrowseTable`」的整表路径上。
- **MariaDB 上的整表导出**：无自动化覆盖（见「已知限制」），也未有记录在案的手工验证。
- **日志轮转**：文件增长速率未测（只在验收短跑里观察过写入成功）。
- `Objects` 页第二页（> 500 个对象）与对象树分页仍未覆盖（`v0232` 脚本按 1 表 1 视图构造数据）。
