# 产品定位与范围

## 问题

成熟数据库客户端（例如 Navicat、DataGrip）功能完整，但普遍基于 Electron/JVM，
启动慢、内存占用高；轻量工具又往往牺牲类型精度、连接安全或大结果集体验。

Sqarvo 的目标是同时满足三件事：

1. **原生**：Windows 使用 WinUI 3，Linux 使用 GTK4 + libadwaita，macOS 使用 SwiftUI；
2. **轻量**：快速启动、低空闲占用，数据库能力集中在单个 Rust 后端进程；
3. **不失真**：不把 Decimal 变成浮点、不把 NULL 变成空字符串、不把不同数据库的
   Catalog/Schema 语义压成一个字段。

## 目标用户

- 需要频繁查看/编辑生产或测试库的开发者与 DBA；
- 对启动速度与内存敏感、不希望为一次查询开一个浏览器内核的用户；
- 希望在 Linux 桌面上获得与商业客户端接近体验的工程师。

## 第一阶段范围（Phase 1）

1. 连接配置、测试连接、连接/断开、会话列表；
2. 数据库对象树与元数据浏览（按需、分页）；
3. SQL 编辑器：多标签、语法高亮、执行、取消、历史；
4. 查询结果：分页/分批、类型正确展示、复制、导出；
5. 表数据浏览与安全编辑；
6. 表结构查看与 DDL。

## 明确不做

- **不以 Web 技术实现桌面 UI**：不引入 Electron、Chromium、CEF、WebView2、WKWebView；
- **不复制商业软件资产**：不复制 Navicat 等产品的代码、图标、文案与界面资源，
  不暗示官方关联；
- **不做「什么都支持」的假象**：未实现的能力必须显式报错或标注，不得静默降级；
- **不在第一阶段做远程后端/团队协作**：本地前后端分进程已足够，避免过度设计；
- **不默认上传任何 SQL、结构或数据**。

## 成功标准

- 冷启动到可输入 SQL < 1s（需有可复现的基准测试，不以口号代替测量）；
- 空闲内存占用显著低于同类 Electron 客户端；
- 10 万行结果集滚动与分页不阻塞 UI；
- 断线、取消、只读、事务中、错误等状态始终对用户可见；
- 任何数据库特有类型都能无损往返或明确标注为「不支持」。
