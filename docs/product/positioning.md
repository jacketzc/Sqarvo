# 产品定位

## 一句话

面向开发者的开源、原生、轻量跨平台数据库客户端：启动快、内存低、类型不失真、
本地通信默认安全。

## 要解决的问题

1. 成熟商业客户端（Navicat、DataGrip）功能完整，但基于 Qt/JVM 等重型运行时，
   启动与常驻内存成本高；
2. 轻量工具往往在类型精度（Decimal 变浮点）、NULL 语义、大结果集分页、
   本地凭据安全上做妥协；
3. Linux 桌面长期缺少体验接近商业产品的原生数据库客户端。

## 目标用户

- 每天查看/编辑测试库与生产库的开发者、DBA；
- 对启动速度、内存占用敏感，不愿为一次查询启动浏览器内核的用户；
- 在 Linux 桌面工作、希望获得原生体验的工程师；
- 希望自行扩展数据库驱动的团队（开源、驱动 SPI 清晰）。

## 差异化（设计目标）

| 维度 | Sqarvo 的目标 | 说明 |
|---|---|---|
| UI 技术 | WinUI 3 / GTK4+libadwaita / SwiftUI | 不使用 Electron、Chromium、WebView |
| 资源占用 | 快速冷启动、低空闲内存 | 需要基准测试数据后才能对外宣称具体数字 |
| 数据库能力 | 集中在单个 Rust 后端进程 | 三端共享同一套连接、执行、事务与类型逻辑 |
| 类型保真 | NULL ≠ 空串；Decimal 不走浮点；区分有无时区 | 无法映射的类型显式标注，不静默降级 |
| 大结果集 | 分批拉取、虚拟化、明确上限 | 不靠调大 gRPC 消息上限解决 |
| 本地安全 | Unix socket 0700/0600 + 每进程 token | 拒绝非回环 TCP；凭据交给系统凭据存储 |
| 扩展性 | 项目自有 Driver SPI，内置 crate | 不泄露第三方驱动类型到公共接口 |

> 以上是设计目标，不是已完成的实测结论。竞品对比若用于对外材料，必须先做可复现基准测试，
> 并核实对方许可证与功能描述，避免不实陈述。

## 与常见产品的差异（定性）

- **Navicat**：商业闭源，功能覆盖广；Sqarvo 以开源、原生轻量、可扩展驱动为差异点，
  不复制其代码、图标、文案或界面资源，也不声称任何关联。
- **DBeaver**：开源、JDBC 驱动生态成熟，基于 Java/SWT；Sqarvo 的差异在于原生 UI 与
  Rust 后端带来的资源占用与启动速度（待实测），以及更严格的类型模型。
- **DataGrip**：商业、JVM；Sqarvo 不做 IDE 级 SQL 智能补全，先聚焦日常连接、执行与浏览。

## 非目标

- 不做 Web 版或浏览器内运行；
- 第一阶段不做远程后端、团队协作、云端同步；
- 不做「功能数量竞赛」：没有需求、测试与错误处理的功能不进入发布范围；
- 不做数据库服务端代理、审计或权限管理系统。

## 成功标准（可验证）

- 冷启动到可输入 SQL 的延迟有基准数据，并优于同类 Electron 客户端；
- 空闲内存与峰值内存在固定数据集下有测量记录；
- 10 万行结果集滚动与分批拉取不阻塞 UI；
- 所有数据库特有类型要么无损往返，要么在界面上明确标注「未完全支持」；
- 本地 IPC 在默认配置下不暴露到网络，且无凭据写入日志。
