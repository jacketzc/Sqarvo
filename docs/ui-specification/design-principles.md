# UI 设计原则

## 基本原则

- 三个平台使用各自原生控件与交互习惯；功能与核心语义一致，不追求像素级一致；
- 键盘可达：常用操作必须有快捷键，且遵循平台约定（Windows/Linux 用 Ctrl，macOS 用 ⌘）；
- 状态必须显式：Loading / Empty / Success / Error / Cancelled / Disconnected 六种状态
  都要有明确呈现，不用「空白」暗示；
- 危险操作按风险提示：删除、覆盖、批量更新、无 WHERE 的 UPDATE/DELETE 必须警告；
  普通查询不加无意义确认框。

## 自解释优先，不靠文字说明

界面应当**靠形态自解释**：控件的位置、分组、可点性、可用态本身表达「这是什么、会发生什么」。
解释性文字是设计没做到的补救，不是设计的一部分。

- **不加流程说明段**。面板底部不写「这里的改动是草稿，点应用才生效，关闭会丢弃」这类文字：
  用「应用」按钮的可用态、标题旁的「有未应用的更改」标记、关闭即回到已应用状态来表达。
  用户点两下就能发现规则，读一段话反而慢。
- **术语不翻译**。数据库客户端的读者认识 `=`、`≤`、`LIKE`、`asc` / `desc`、`IS NULL`。
  写「= 等于」「▼ 降序」既占宽度又多一遍信息；下拉只放符号或 SQL 词。
- **说明只在需要时出现**：tooltip（悬停才看）、错误提示（真的出错）、空态一行（列表为空时
  说明「无筛选条件」这类状态，而不是操作指导）。
- **不做整行拉伸**。一行里的控件按内容宽度排列、左对齐；空白属于布局，不属于控件。
- 判断标准：把面板截图交给没用过的人，他能不能在不读文字的情况下点对第一下？不能就是
  设计问题，不要用文案盖过去。

## 布局

区域、尺寸与对象矩阵见 [workspace-model.md](workspace-model.md)；这里只给层次。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 窗口外壳：标题（对象 @ 库 (连接)）+ 菜单                          │
├──────────────────────────────────────────────────────────────────┤
│ 主工具条：连接 / 新建查询 │ 表 / 视图 / 函数 / 查询（打开 Objects 页）│
├───────────────┬──────────────────────────────────┬───────────────┤
│ 对象树         │ 标签条（固定 Objects + 对象标签） │ 信息面板       │
│ （按需加载）    ├──────────────────────────────────┤ 连接 / 库 / 表 │
│               │ 表格工具条（事务/排序筛选/列/导出）│ DDL ⇄ 表信息   │
│               ├──────────────────────────────────┤ （常驻）      │
│               │ 数据网格 / 结果网格               │               │
├───────────────┴──────────────────────────────────┴───────────────┤
│ 状态栏：行操作 · 分页 │ SQL 摘要 · 刷新时间（表信息在表格工具条） │
└──────────────────────────────────────────────────────────────────┘
```

标签与会话一一对应（ADR 0021）；表格分页与总数口径见 ADR 0022；三端只要求区域与语义一致，
控件按平台原生（ADR 0023）。

### 可交互的列表按表格绘制

工作区里「列出一批对象」的界面（固定 `Objects` 页、搜索结果、将来的对象索引）都用表格行
状态，不另造一套行样式：

- **行状态只有一个来源**：悬停 `alpha(currentColor, 0.04)`、选中 `alpha(@accent_color, 0.25)`、
  行分隔线 `alpha(currentColor, 0.10)`、行高 32 —— 与数据网格同一口径（`theme.rs` 的单测
  锁住四条规则）。不要挂 `.navigation-sidebar`：它把选中态改成 10% 灰，和网格不是一套；
- **图标复用对象树的种类映射**（`backend::metadata::kind_icon`）：同一个对象在树、列表、
  标签里长得一样，不按页面各写一份；
- **单击 = 选中，双击 / 回车 = 打开**，与对象树统一。选中是「看这个对象的详情」（同步信息
  面板），不是「打开它」——列表因此不会因为点一下多出一个标签 / 一条会话；
- **选中态要活过联动刷新**：树里的选中若只换了同作用域的相邻节点，列表不重发请求、不清空
  行、不丢选中。

## 图标

图标是**语义**，不是装饰：只含图标的按钮，形状必须让人一眼读出动作（筛选 = 漏斗、
导出 = 下载/存盘、取消 = 实心方块、列显隐 = 眼睛）。找不到合适形状时补一个**项目自有
符号图标**（`frontend/linux/resources/icons/`，编进 GResource、随主题重着色），不要用
语义相近但会误导的替身（例如用放大镜表示筛选、用纸飞机表示导出）。

尺寸只有**一个**（`frontend/linux/src/layout.rs` 的 `ICON_BOX`，`src/icons.rs` 是唯一
构造入口）：每个图标都画在 16 × 16 里，基准就是状态栏行操作里的 `+`——长宽都不超过它，
而且两维都与它相等。禁止按单个图标凭喜好调大小：

| 尺寸 | 像素 | 适用 |
|---|---:|---|
| 基准盒 | 16 × 16 | 绝大多数图标（`+`、`−`、分页箭头…），基准就是状态栏的 `+` |
| 光学补偿 | 逐图标登记 | 只有墨迹比例明显偏离基准的字形，见下表 |

光学补偿表（`frontend/linux/src/icons.rs` 的 `OPTICAL_PX`，数字旁边是**截图量出来的**
墨迹长宽，不是估计值）：

| 图标 | 像素 | 墨迹 | 理由 |
|---|---:|---|---|
| 应用 `✓` | 14 | 12 × 8 | 16px 时 14 × 10，比 `+` 宽一圈，显得偏大 |
| 刷新 `⟳` | 14 | 14 × 14 | 16px 时外框贴满整盒，显得偏大；再往下缩（≤13px）描边落到 1.3px 以内就发虚 |
| 放弃 `↶` | 18 | 13 × 11 | 16px 时 11 × 9，弧线窄，看着不够宽 |
| 取消 `■` | 18 | 12 × 12 | 16px 时 10 × 10，实心方块显小 |

> 缩放有**下限**：主题符号图标的描边约 1.6px（16px 网格），缩到 13px 以下描边不足
> 1.3px，渲染出来就是「发虚」——所以宁可略大也不再往下调。
>
> 目标是让**墨迹**落到基准 `+`（11 × 11）附近，而不是让每个图标的长宽都相等：`✓` 天生
> 宽扁、`↶` 天生窄，靠统一盒子抹不平。所以规则是「基准 16 + 少数逐图标补偿」，每个补偿
> 都必须带实测墨迹；改数字先重新量，别凭手感。v0.2.3.3 的三档（16 / 18 / 14）就是因为
> 补偿方向不一致被推翻过一次，这一版把每个数字的理由钉在注释里。

图标按钮的命中区固定 28 × 24（高度取 §11 的最小点击区），不随图标变化。
`--qa-layout-audit` 会断言每个图标按钮都符合这套标准（命中区 28×24、图标一律 16px），
所以「这次调一个、下次又调一个」会在自检里直接失败。

## SQL 编辑器

不能使用普通多行输入框替代。逐步具备：

- 大文本高效编辑、行号、当前行高亮、选区与缩进；
- 多方言语法高亮；
- 查找/替换；
- 执行全部 / 执行当前语句；
- 自动补全（基于元数据，渐进引入）；
- 明确显示只读、事务中、已断开状态。

## 结果网格

- 虚拟化渲染，禁止一次性创建全部行控件；
- 分页/分批拉取，首批默认 500 行（表浏览见 ADR 0022，查询结果见 ADR 0005）；
- 列宽调整、排序、筛选、复制；
- NULL 显示为独立的「NULL」样式，不与空字符串混淆；
- 二进制显示为占位并提供查看/导出；超大文本标记截断；
- Decimal 按原文显示，不做浮点格式化；
- 编辑状态：脏标记、提交、回滚、只读模式明确。

## 空状态与错误

- 空结果与「未执行」必须区分；
- 错误展示：用户可读文案 + 稳定错误码（可展开查看），不暴露堆栈与凭据；
- 取消后展示「已取消」，而不是错误。

## 平台注意

- Windows：跟随系统主题与 DPI，使用 WinUI 原生菜单与文件选择器；
- Linux：遵循 GNOME HIG；非 GNOME 环境不假设 Shell 特性；GTK 更新只在主线程；
- macOS：使用系统菜单栏、工具栏、快捷键；使用 Keychain 存取凭据。

## 禁止

- 使用 Electron / Chromium / WebView 实现界面；
- 在 UI 线程执行数据库 I/O 或大文件处理；
- 用占位数据或假成功状态掩盖未实现功能。
